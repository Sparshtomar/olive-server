# Architecture

How a request moves through the API, where each conventional layer lives, and the
rules that keep it that way. Decisions and their reasoning are in [adr/](adr/README.md).

## If you are looking for…

The code is grouped **by feature** ([ADR 0001](adr/0001-modules-by-feature.md)), so the
usual layer names are files inside each module rather than top-level folders.

| Conventional name    | Here                                                              | Notes                                                                           |
| -------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| Controllers / routes | `src/modules/<name>/<name>.routes.ts`                             | Fastify plugins. HTTP in, validation, status codes. No logic.                   |
| Services             | `src/modules/<name>/<name>.service.ts`                            | Business rules. Depend on repositories and interfaces only.                     |
| Repositories / DAO   | `src/modules/<name>/<name>.repository.ts`                         | Drizzle queries. Private to the module.                                         |
| Models / entities    | `src/db/schema.ts`                                                | Drizzle table definitions; one file, one source of truth.                       |
| DTOs / validators    | `packages/shared/src/*.ts` (`@sparshtomar/olive-shared`)          | Zod schemas shared with the app ([ADR 0002](adr/0002-shared-zod-contract.md)).  |
| Mappers              | `src/modules/<name>/<name>.mapper.ts`, `src/ai/gemini/mappers.ts` | Rows → API shapes; loose model output → strict domain.                          |
| Interfaces / ports   | `src/ai/types.ts`                                                 | `MealAnalyzer`, `ReportExtractor`, `HealthAssistant`; services depend on these. |
| Adapters             | `src/ai/gemini/`, `src/ai/mock/`                                  | Implementations chosen in `src/ai/index.ts`.                                    |
| Middleware           | `src/plugins/`                                                    | Auth (`current-user`), error shape (`error-handler`).                           |
| DI container         | `src/container.ts`                                                | The one place concrete classes are constructed and wired.                       |
| Config               | `src/config/env.ts`                                               | Zod-validated environment; the process refuses to start on a bad one.           |
| Migrations           | `drizzle/*.sql`, applied by `src/db/migrate.ts` at boot           | Generated by `npm run db:generate`.                                             |
| Seeds                | `src/seed.ts` (`npm run db:seed`)                                 | Creates the demo user; same code the app's demo button uses.                    |
| Entrypoint           | `src/server.ts`                                                   | Env → migrations → DB → container → app → listen; graceful shutdown.            |
| Tests                | `test/*.test.ts`                                                  | Integration against Postgres with a fake AI; architecture rules.                |

## A request, end to end

```
POST /meals/analyze/photo
  │
  ├─ plugins/current-user        x-user-id → request.user (401 if unknown)
  ├─ @fastify/rate-limit         per-user AI allowance (Redis-backed when REDIS_URL is set)
  ├─ modules/meals/meal.routes   multipart read, magic-byte sniff → 415 if not an image
  ├─ modules/meals/meal.service  analyzer.analyze(input)            ← MealAnalyzer interface
  │     └─ ai/gemini             structured output, model fallback chain, timeout
  │           └─ ai/gemini/mappers   clamp + map loose output → strict MealDraft (Zod)
  └─ plugins/error-handler       anything thrown → { error: { code, message } }, x-request-id on every reply
```

Writes (`POST /meals`) go `routes → service → repository` inside one transaction and
are idempotent on `(user_id, client_id)`.

A chat turn (`POST /chat/messages`) is the same shape with one extra step: before
calling the model, `ChatService.buildContext` renders the user's profile, today's meals
and every lab marker as text, so the answer is grounded in their data
([ADR 0007](adr/0007-grounded-assistant.md)). The turn is persisted only after the
model has answered.

## Dependency direction

```
        app.ts / server.ts / container.ts        composition root
                     │
   ┌─────────────────┼──────────────────┐
 plugins/        modules/*/index.ts     (modules may use each other here only)
                     │
            routes → service → repository
                     │
          lib/   db/   ai/   config/    infrastructure: imports nothing above
```

Every arrow is an ESLint `no-restricted-imports` rule in [eslint.config.mjs](../eslint.config.mjs);
the module anatomy is checked by [test/architecture.test.ts](../test/architecture.test.ts).

## Operability

- **Health:** `GET /health` round-trips the database with a 2 s budget; 503 if it loses.
- **Tracing:** every response carries `x-request-id` (honoured if the caller sends one) and
  the same id is on every log line for that request.
- **Shutdown:** `SIGTERM` stops accepting, drains in-flight requests, closes the pool.
- **Limits:** body 512 KB (1 MB for meal saves), uploads 5–15 MB by type, per-user AI rate limits.
- **Docs:** `GET /docs` — OpenAPI generated from the same schemas that validate requests.

## Scaling plan

What changes, and the measurement that would trigger it. Until a trigger fires, the
simpler design is the correct one ([ADR 0005](adr/0005-one-postgres.md)).

| Trigger                                   | Change                                                                                             |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------- |
| A second API instance                     | Set `REDIS_URL`; rate limits become shared ([ADR 0006](adr/0006-optional-redis.md)). Nothing else. |
| `/days/:date` p95 > 300 ms                | Materialise per-day totals on write (a table, not a cache).                                        |
| AI p95 > 10 s, or providers need > 30 s   | Job table + worker in this codebase, push on completion ([ADR 0004](adr/0004-synchronous-ai.md)).  |
| Sustained read load saturates the primary | Read replica for trends/insights only — never the screen after a write.                            |
| Photos > a few GB                         | Move `meal_photos` bytes to object storage; keep the row as the index.                             |
| A third client (web dashboard, partner)   | Generate clients from the OpenAPI document ([ADR 0002](adr/0002-shared-zod-contract.md)).          |
